# Machine-Wide Registry (`~/.conductr`)

The machine-wide registry declares every project this host is responsible for.
A single `conductr setup spawn` command reads the registry and brings every
`status = "active"` project to a running state.

## File location

`~/.conductr` — one file per host, not per repository.

## Schema

```toml
# Optional top-level defaults block.
# Values here seed the per-repo .conductr files that spawn generates.
[defaults]
human_assignee      = "Luan-vP"          # GitHub username for human-labelled issues
local_provider      = "ollama"           # local AI provider (ollama | llamacpp | pi)
cadence_orchestrate = "*/30 * * * *"     # cron expression for the orchestrate job
cadence_idle        = "17 * * * *"       # cron expression for the idle job

# One [[projects]] entry per project.
[[projects]]
tag    = "conductr"               # unique slug — used as the tmux session name suffix
repo   = "Luan-vP/conductr"      # GitHub owner/repo
path   = "/home/dev/developer/conductr"  # absolute path to the local clone
status = "active"                 # "active" | "pending"
```

### `status` values

| Value | Meaning |
|-------|---------|
| `active` | Fully provisioned: repo cloned, per-repo `.conductr` present, cron entry installed. |
| `pending` | Declared but not yet provisioned. `spawn` skips these with a reminder line. |

### Tag rules

- Tags must be unique across all `[[projects]]` entries.
- Duplicate tags are rejected at parse time with a clear error message.
- Legal characters: `[a-z0-9-]` (same as `project_tag` in per-repo `.conductr`).

## `conductr setup spawn` workflow

For each `active` project in the registry:

1. **Verify local clone.** If `path` doesn't exist, attempt
   `git clone git@github.com:<repo> <path>`. Clone failures are logged and
   skipped — the rest of the pass continues.

2. **Verify per-repo `.conductr`.** If `<path>/.conductr` is absent, generate
   one from the registry entry, seeded by `[defaults]`.

3. **Run `cadence sync`** from `<path>`. Installs or refreshes the cron entry.

4. **Verify tmux session.** If `conductr-<tag>` is missing, create it with
   `cwd = path`. Claude is **not** started here — the next cron fire will do
   that via `conductr orchestrate`.

### Per-project status icons

| Icon | Meaning |
|------|---------|
| `✓ already provisioned` | All steps were already in place. |
| `↺ provisioned this pass` | One or more steps were performed this run. |
| `⚠ skipped (<reason>)` | Clone failed; project skipped without aborting the pass. |

## CLI reference

```
conductr setup spawn               # provision all active projects, idempotent
conductr setup spawn --dry-run     # print plan only, no changes
conductr setup spawn <tag>         # provision a single project by tag
conductr setup spawn --include-pending   # also try pending entries
conductr setup spawn --registry <path>   # override registry path
```

## Generated per-repo `.conductr`

When `spawn` creates a missing per-repo `.conductr`, it uses the following
template (values from `[defaults]` fill the placeholders):

```toml
# Project config for <tag> — generated by `conductr setup spawn`.
# Edit fields as needed.

project_tag = "<tag>"
repo        = "<owner/repo>"

[band]
human_assignee = "<defaults.human_assignee>"

[local]
provider = "<defaults.local_provider>"

[cadence]
orchestrate = "<defaults.cadence_orchestrate>"
idle        = "<defaults.cadence_idle>"
```

The user can override any field in the per-repo file after first spawn.
The registry `[defaults]` are only used at generation time.
